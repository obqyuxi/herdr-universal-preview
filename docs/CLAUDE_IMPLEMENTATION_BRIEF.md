# Herdr Universal Preview：Claude Code 完整开发指令

> 本文是实际实施任务书。请先完整阅读，再在独立项目中核查、开发、构建和测试。以执行时安装版本、生成的类型定义、源码和实际运行结果为准；本文中的新接口、阈值、目录和验收指标是项目设计要求，不代表 Herdr 已有能力。

## 00. 任务、背景与最终成果

你担任本项目的技术负责人和实施工程师，负责产品交互、Herdr Mod、Rust/macOS 原生集成、测试、打包和交付。

项目名称：`herdr-universal-preview`。
默认项目目录：`~/Projects/herdr-universal-preview`。如果当前目录已经是该项目，直接使用；已有文件必须先读，禁止重新初始化覆盖。

用户的真实目标：

**保留 Herdr 现有的 Agent、终端、工作区和文件树，让用户在同一个 Herdr 主窗口内随时打开网页，以及查看代码、Markdown、图片、PDF、Office 文档，播放视频和音频。点击文件后就能查看，不需要反复切换 Chrome、Finder、预览或 QuickTime。**

用户使用 macOS Apple Silicon，有 16GB 内存的 Mac mini 和 64GB 内存的 MacBook Pro。实际开发机器、系统版本、内存和 Herdr 版本必须实测，不能从历史描述推定。用户使用 Codex CLI、Claude Code CLI、Kimi Code 等，不需要为本项目更换 Agent 或引入 OMP。

交互参考是 Codex 桌面端的统一工具工作区：有文件、变更、终端，能在应用内部打开网页。参考功能组织即可；不研究或推测其未公开实现，不复制品牌、专有代码或素材。

这是一个增强现有 Herdr 的项目，不要求重做 Herdr，不要求自建大模型，不要求开发独立 Electron IDE。你必须实际推进实现；发现一个能力受阻时，记录原因并继续其他可交付工作。

### 成果定义

交付分成两个真实形态，必须明确标注，不能混为一谈：

- **普通 Mod 版**：在原版 Herdr 上运行当前 API 能支持的预览能力。缺少原生承载能力时，明确显示缺项。
- **完整增强版**：如原版尚无所需接口，在独立个人构建的 Herdr 中加入最小原生视图扩展，实现同窗口网页、文档、音视频预览。这是用户最终希望使用的形态。

最终必须说明每项能力依赖哪一种形态。不能把个人构建的截图当成原版安装一个 Mod 就有的功能。

## 01. 不可降级的验收边界

1. 网页必须是真实可交互网页：鼠标点击、输入、滚动、链接、前进后退、刷新可用。
2. 视频必须真实播放且有声音、暂停和拖动进度；首帧、封面、媒体信息不算播放。
3. 音频必须真实播放；显示波形、时长、文件名不算播放。
4. 文档必须展示实际内容；显示路径、元数据、文件图标不算预览。
5. 文件树和预览可以同时可见；打开文件不能强制把文件树替换成预览后无处导航。
6. 页面和文件内容必须位于 Herdr 主窗口的可布局区域内。外部软件、独立伴随窗口、浮动假嵌入窗口、截图轮播均不能作为这项验收通过的证据。
7. `qlmanage -p`、`open`、启动系统浏览器只允许作为用户主动选择的备用操作，不能替代核心实现。
8. PDF 转成图片可以作为明确标注的降级模式，但不能宣称保留了原生文本选择、搜索等能力。
9. “所有文件都能看”是持续扩展方向，不得承诺所有编码、DRM、损坏文件、密码文件或复杂 Office 特性均支持。必须给出格式、编码和样例级的真实支持矩阵。
10. 功能测试失败与合理不支持要区分。普通 DOCX/XLSX/PPTX 样例无法预览，就是对应核心需求未完成；不能只增加“外部打开”就把该项改为已完成。
11. 静态检查、编译通过、单元测试通过、真正 GUI 验收通过是四件不同的事，必须分别记录。

## 06. 测试隔离：应用与 core 分别隔离

**只换一个 Herdr App 配置目录，不足以证明已与正式 core 会话隔离。** 必须检查实际连接目标、状态路径和共享文档。

实施要求：

1. 测试配置、缓存、浏览器 profile、日志使用项目内独立目录。
2. 根据 `hc` 当前版本支持的真实机制，建立独立测试 core、socket/地址与会话存储。不要编造环境变量。
3. 若暂时无法证明 core 隔离，仅做离线检查和不连接正式 core 的原型；不得写正式空间、标签或布局。
4. 测试个人构建使用明确名称，例如 `Herdr Preview Dev.app`，独立 Bundle ID 和启动入口；正式 App 保持原样。
5. 检查上游启动时的命令链接修复、自动更新、配置迁移行为，防止测试 App 把正式 `herdr-app` 命令指向自身。
6. 脚本使用明确的测试二进制绝对路径和显式测试配置，不依赖容易混淆的 PATH 默认命令。
7. 测试程序不得自动安装上游正式更新覆盖本项目补丁；个人构建更新流程单独记录。
8. 只停止本项目启动并核实归属的进程，不用 `pkill herdr` 等宽泛清理。
9. 测试权限只授予需要的测试程序；不修改正式应用签名、Info.plist、隔离属性或系统安全设置。
10. 无需复制正式 SSH 私钥、Agent 登录资料、历史对话或浏览器 Cookie 到测试环境。

在 `ENVIRONMENT.md` 记录测试前后正式 Herdr/core 的连接身份和进程状态。只读观察现有正式配置，不执行会改变其状态的探测。

## 07. 先验证最高风险：同窗口原生视图原型

不要先完成大量界面美化，再发现原生承载不可用。环境核查之后，尽早完成一个最小垂直原型。

### 原型内容

在隔离测试 Herdr 中，一侧放测试终端，另一侧放真实原生视图，分别验证：

- `WKWebView` 加载本地测试网页，按钮和中文输入框可交互。
- `PDFView` 或适合的原生文档视图展示两页 PDF。
- `AVPlayerView`/`AVPlayer` 展示测试视频，能播放和暂停。
- `QLPreviewView` 展示普通 DOCX/XLSX/PPTX 样例，记录实际能力。

这些是候选技术；以当前 SDK、绑定和实际运行验证为准。不允许直接把 iOS 的 UIView/QLPreviewController 示例当成 macOS 的实现。

### 必须验证的宿主问题

视图附着、分屏拖动、窗口缩放、裁剪、标签隐藏、标签关闭、恢复焦点、中文输入法候选框、复制粘贴、Retina 缩放、窗口最小化和恢复。

命令面板、右键菜单、弹窗、确认框出现在原生区域上方时，必须可见且能点击。禁止只把 NSView 置于最上层，导致 Herdr 弹窗被盖住或点击穿透。可采用经过验证的遮挡协调策略；若暂时隐藏原生视图，不能销毁其状态、泄露底层点击或把隐藏截图当作实时内容。

同时显示两个预览区域时也要验证，不能只测试单一全屏视图。

截图证据必须确认包含原生子视图。若 Herdr 自带截图仅捕获 GPUI 层，不能据此声称原生视图不可见或已经验收；使用可用的窗口级捕获或经授权的 GUI 截图，并说明方法。

### 决策门

原型失败时定位具体原因：SDK、绑定、布局、焦点、遮挡、签名、权限或底层架构。记录已经尝试的方案和证据。可继续纯 Mod 模块，但不得宣布完整路线已可用。

优先维持 Rust/GPUI 架构。CEF、额外常驻浏览器进程或重写桌面外壳仅在 WKWebView 等路线经验证不满足核心目标时提出，需说明体积、维护、兼容性和安全成本，并取得用户确认。

## 08. 产品交互：用户实际如何使用

### 8.1 布局

默认保留工作区/Agent 导航和终端，新增可调整宽度的预览区域。文件树可以放在侧栏，预览区放在 Agent 旁边；窄窗口允许折叠，但不能强制用户离开 Herdr。

应支持两种入口：文件树点击打开内容；工具栏“打开网页”创建浏览器页。另提供“打开文件…”使用系统选择器选择项目外文件，仅授予选中文件及必要资源的最小访问范围。

### 8.2 文件打开规则

- 单击文件：更新一个可复用的临时预览标签，避免点击十次生成十个固定标签。
- 双击或“固定”：保留为固定标签。
- 再次打开同一资源：优先激活已有标签；“在另一区域打开”才创建第二视图。
- 文件树与内容保持同时可见；选中文件清晰高亮。
- 目录点击只展开/折叠，不把目录误当文件。
- 文件名有中文、空格、单引号、`#`、`%`、表情时都正常处理。
- 不因自动刷新跳回树根，不丢失展开状态和预览阅读位置。

### 8.3 标签与项目隔离

标签显示名称、类型、加载/错误状态、关闭入口。长名称省略但提供完整路径提示。

每个标签绑定打开时的 `machine_id + workspace_id + canonical_path/URL`，不能依赖当前 Agent 目录重新解释。切换项目后不能把 A 项目的同名文件替换为 B 项目内容。

记住文件阅读位置、PDF 页码和缩放、媒体进度；恢复时不自动播放。浏览器导航历史单独维护。会话恢复不得重新提交网页表单、自动批准权限或重复执行有副作用的操作。

### 8.4 快捷键与焦点

先读取现有快捷键，再设计有范围的映射。`Cmd+L` 可用于聚焦本预览浏览器地址栏；`Cmd+F` 用于当前内容搜索；`Cmd+W` 只有预览拥有焦点时才关闭当前预览。

不得全局拦截终端 `Ctrl+C`、`Ctrl+D`、Agent 输入、系统剪贴板和 macOS 中文输入法。快捷键未实现就不显示提示；不要留下只能点击无反应的装饰按钮。

### 8.5 状态与错误

统一显示：准备加载、加载中、可查看、已变化、暂不可用、失败、不支持。

失败时提供清楚原因和可行操作：重试、重新选择、授权、查看源码、手动外部打开。禁止空白屏、永久转圈或把二进制乱码塞入代码编辑器。

## 09. 类型识别与内容路由

建立可测试的路由层，不把所有逻辑堆在 Files 的点击回调里。

识别结合文件扩展名、UTType/MIME、受限长度的文件头和实际解码结果。扩展名只作线索；目录、符号链接、损坏文件、未知二进制、无扩展名文本都必须处理。

建议路由：

| 内容 | 首选路径 | 限制 |
|---|---|---|
| 文本/代码 | Herdr Editor 或现有文本组件 | 只读、大文件有界读取 |
| Markdown | 原生富文本或隔离静态渲染器 | 补齐图片/表格；不得执行任意脚本 |
| 图片 | 原生图片组件/系统解码 | 尺寸探测、缩放、动画能力需验证 |
| PDF | PDFKit `PDFView` | 选择/搜索只对实际文本层成立 |
| Office | `QLPreviewView` 等系统预览 | 样例验证，复杂特性不承诺 |
| 视频/音频 | AVKit/AVFoundation | 容器和编解码器分别验证 |
| 网页/HTML | `WKWebView` | 普通浏览与本地静态内容使用不同信任策略 |
| 未知文件 | 安全的文件信息与明确不支持状态 | 外部打开仅用户主动触发 |

所有预览默认只读。查看文件不能改写源文件、改动 Git 状态、执行 Shell 或上传内容。

## 10. 各类内容的具体要求

### 10.1 文本、代码、JSON 与 CSV

复用现有 Editor，不开发新的代码编辑器。显示行号、语法高亮、自动换行开关、复制选区、文件内查找。首次交付可对部分语言降级为纯文本，但须明确。

UTF-8 和 BOM 要正确处理；无法确定编码时提示，不把错误解码当原文件内容。其他编码按实际需要补充，不静默改写文件。

JSON 提供源码与格式化只读视图；无效 JSON 显示真实错误，不修改原文。CSV 提供只读表格与源码切换，处理引号、逗号、换行单元格和大行数；不得把以 `=` 开头的内容作为公式执行。

大文件先受限读取并明确提示范围；不能先读取整个文件再截断字符串，伪装成大文件优化。

### 10.2 Markdown

支持常见标题、列表、引用、分割线、代码块、表格、链接和本地图片；相对图片路径相对于文档目录解析，并接受授权根目录校验。

渲染和源码切换保留位置。外链图片默认不静默联网，提供加载提示或可配置授权。图片缺失必须有占位和替代文字。

HTML 片段与链接需安全处理；默认禁用脚本、危险协议和越权文件读取。Mermaid 是增强项，不能用“支持 Markdown”隐含其已支持。

### 10.3 图片

至少验证 PNG、JPEG、WebP、GIF、SVG。提供适应区域、100%、缩放、拖动查看、透明棋盘背景和尺寸信息。

GIF 若只能显示首帧，明确标注并计入功能缺项，不宣称动画已支持。SVG 中脚本、外链资源和外部文件引用按不可信内容处理。

解码前检查像素数量和资源预算。超大图优先缩略解码或请求用户确认，不因体积小而忽略压缩后巨大像素的风险。HEIC、TIFF、AVIF 等作为经实测添加的格式。

### 10.4 PDF

多页滚动、上一页/下一页、跳页、适应宽度、缩放、页数指示属于基础能力。具有文本层的样例必须能选中并复制中文和英文。

密码保护文件要求用户输入密码，密码只存当前内存、不进入日志和 Git；错误密码、损坏文件均有明确状态。扫描 PDF 不承诺 OCR。

缓存页面按可见范围管理。若采用系统 PDFView，由系统负责的缓存与本项目自管缓存分别说明，不宣称能够严格限制系统渲染进程的总内存。

### 10.5 Office

用真实多页 DOCX、多工作表 XLSX、多幻灯片 PPTX 验证内嵌预览。检查正文、中文、表格、图片和后续页面能否看到，不能只看封面。

XLSX 只读展示不等于重新计算公式，不运行宏或外部数据连接。PPTX 不承诺动画与放映完全一致，DOCX 不承诺所有排版与 Word 一致。

系统预览缺少所需能力时，评估本地替代：受控文档解析、展示缓存值、经许可的本地转换。若使用转换，显示“转换预览”、来源更新时间和限制，不覆盖源文件。

严禁为了实现 Office 预览把文件交给在线 Office/Google Viewer 或任何第三方云服务。额外转换依赖需说明并征得同意。

### 10.6 视频和音频

提供播放/暂停、进度、拖动、总时长、音量/静音；视频保持比例，音频提供清晰的当前播放状态。

默认点击打开不自动播放；同一应用默认只有一个主动播放的本地媒体。切换到其他预览时默认暂停，可在后续设置中允许后台播放。关闭标签立即停止声音并释放相应资源。恢复会话保留位置但不恢复播放。

至少记录实际测试样例的容器、视频编码、音频编码与播放结果。MP4 或 MOV 扩展名本身不构成兼容保证。错误解码、无音轨、只有音轨、未知时长、文件被替换等状态要可解释。

不为每次播放复制完整大视频，不全量转 Base64，不默认转码。字幕、倍速、波形、画中画均为后续增强，不能阻塞基础播放。

## 11. 内嵌浏览器：完整基础体验

### 11.1 基础行为

工具栏含地址栏、前进、后退、刷新/停止、加载状态、网页标题和关闭。无前进后退历史时正确禁用按钮。

支持普通 HTTP/HTTPS、明确端口的 localhost 开发站、本地 HTML。地址标准化要正确处理 `localhost:3000`、`127.0.0.1:5173` 和 IPv6 回环地址，不把它们错误解释成搜索词。默认不把未知输入自动提交搜索引擎。

文件路径应通过安全 URL 编码转换，不能简单拼接 `file://`。仅在本地开发或用户明确访问时使用 HTTP，不静默把所有 HTTPS 失败转为 HTTP。

### 11.2 网页交互

验证文字选择、中文输入、复制粘贴、滚动、表单、页面内链接、前后导航、刷新和 JavaScript 更新。

`target=_blank` 和用户触发的新窗口在 Herdr 浏览器标签中处理；非用户触发的弹窗默认阻止并提示。文件上传使用用户明确选择的文件，下载需由用户确认保存位置；不要自动调用 Shell 或外部程序处理网页协议。

处理加载失败、开发服务器未启动、证书错误、重定向、WebKit 内容进程终止。不得通过关闭证书校验、Web 安全或同源保护来“解决”问题。

### 11.3 开发预览

测试一个真实的小型本地开发站，包含按钮、输入框、导航、图片和热更新。修改源码后，验证开发服务器的 HMR/WebSocket 更新可以在内嵌页面显示；不要把每秒整页刷新称为 HMR。

前端开发端口不得写死为 3000；端口被占用时不停止别人的服务，选择可用端口并记录。

### 11.4 HTML 的两种模式

- **静态文件预览**：默认禁用脚本和外部网络，允许读取已授权资源范围内的 CSS、图片等，阻止越界路径。
- **交互运行模式**：用户明确为该文件/目录/开发源启用脚本和必要网络能力；显示信任状态。需要开发服务器时由用户授权运行，不执行文件内声明的安装命令。

普通手动网页浏览允许网页自己的 JavaScript，但不授予任何 Herdr 文件系统、Shell、Agent 或控制接口权限。

### 11.5 浏览器资料与隐私

使用本项目独立 WebKit 资料空间；明确临时模式和需要持久登录时的行为。不要读取或复制用户日常 Chrome/Safari Cookie、密码、扩展或历史。

本地文件和不可信静态文档与普通网页隔离，不共享宿主特权。提供清除浏览数据入口。恢复标签时不得把 URL 中敏感令牌、表单数据、密码写入通用日志。

不承诺支持 Chrome 扩展、所有网站登录、DRM 视频、Passkey 或与 Chromium 完全一致的渲染；记录实际失败原因和可用替代方式。

## 12. 原生宿主扩展边界

若确需修改 Herdr，目标是一个窄的原生内容承载接口，加若干具体渲染器，不是每增加文件类型就改一遍核心业务。

### 模块边界

- Mod：文件树、标签、中文工具栏、用户操作、显示状态。
- 宿主：原生视图创建/布局/焦点/销毁、受控文件访问、生命周期、原生事件。
- 渲染器：网页、PDF、系统文档预览、媒体等具体内容。

接口名称由实现决定。下列能力是**本项目拟新增的接口契约**，不能冒充现有 Herdr API：

`capabilities`、`create`、`load`、`resize`、`setVisible`、`focus`、`performAction`、`dispose`。

动作要按渲染器白名单区分，例如 browser.back、pdf.goToPage、media.pause。禁止提供任意命令执行接口给网页，不把传来的字符串直接拼接进 Shell。

事件至少表达：加载开始、加载完成、失败、标题/地址变更、历史状态、页码变化、播放状态/进度、视图销毁；每条事件包含 view/tab 身份和加载代次。

### 原生工程要求

AppKit/UI 生命周期在正确线程执行；文件探测、远程下载和可安全放后台的重工作不得堵塞主线程。依据框架线程要求处理，不假定所有解码都能随意跨线程。

正确管理强弱引用、delegate、KVO、通知、定时器和回调；视图关闭后不能回调已释放对象。媒体停止需移除观察者，Quick Look 关闭需释放预览项，网页标签关闭需清理本项目 handler 和资源。

原生视图矩形使用经验证的坐标转换、可见裁剪和缩放因子；不把逻辑点当物理像素。支持两个窗口/多个标签时保持各自所有权，不能全局只保留一个 currentPreview。

功能探测明确返回能力和接口版本。原版缺少宿主 API 时，Mod 仍可加载并提供受支持能力；显示“当前版本未提供原生预览”，不要崩溃或偷偷启动外部软件。

不新增会让旧版整个共享布局文档解析失败的结构。优先使用已有 Mod 节点和可忽略的 props；如确有协议变更，必须设计兼容、迁移和回退，并在启用前说明。

## 13. 状态、异步一致性与文件变更

设计并测试下列概念，名称可以调整，但含义不能缺失：

```text
ResourceRef:
  source: local | remote | web
  machine_id
  workspace_id
  authorized_root_id
  canonical_path 或 normalized_url
  display_path
  resource_version: mtime/size/必要时的内容摘要

PreviewSession:
  tab_id / view_id
  resource_ref
  renderer_kind
  request_generation
  state: idle | loading | ready | stale | unavailable | error | unsupported | disposed
  pinned
  visible
  trust_mode
  per_type_view_state
```

这是项目内部模型，不是现有 Herdr 数据结构。不要修改上游模型来强行塞入全部字段；优先保存到本项目自己的持久化状态中。

快速点击 A→B→C 时，A/B 较晚返回的读盘、下载、解码和原生事件不得覆盖 C。所有异步完成都检查资源身份、视图身份、加载代次和销毁状态；支持取消或至少丢弃过期结果。

监听当前打开文件及必要目录，做防抖；不要每次保存递归扫描整个仓库、node_modules 和 .git。原子替换保存、删除、重命名、权限改变都要处理。

文本、图片、Markdown 可在变更后保持位置刷新；PDF 保留有效页码和缩放。媒体文件正在播放时被替换，先暂停并提示重新加载，不继续使用错误句柄。网页交互表单不得因无关文件变更强制刷新。

## 14. 本地安全与权限模型

将本项目的安全边界说清楚：Herdr Mod 本身属于用户信任代码，本项目的路径限制不能保证约束其他恶意 Mod 或同用户高权限程序。我们必须保护的是自己的接口不被网页、文档内容、错误路径或过度授权利用。

- 文件访问使用授权根和真实路径校验，处理 `..`、符号链接、编码绕过和切换文件的竞态。
- 用户选中项目外文件，不代表授权整个 home。必要的兄弟资源范围需要明确。
- 任意网页不得访问本项目原生控制接口；网页内容不能修改授权状态。
- 本地 HTML/SVG/Markdown 的脚本、网络和本地路径策略必须分开控制。
- 不上传本地文件到云，不自动把整个文件内容发送给模型。
- 无授权不访问生产数据库、顾客信息、医疗数据、财务资料或现有 Agent 对话。
- 对 `.env`、密钥、证书等敏感文件显示警示；日志、截图和 Agent 转发均避免自动包含。
- IPC 优先采用受限本地通道；需要网络端口时只绑定回环，并验证认证、Origin、Host 和输入边界，不能仅依赖“端口在 localhost”就认为安全。
- 不暴露通用 exec、无认证 eval、任意文件下载或全盘目录接口。
- 日志默认记录状态和错误代码，不记录文件正文、密码、完整敏感 URL 和授权令牌。

缓存、测试浏览器资料、构建日志均加入 `.gitignore`，同时检查 `git status`/暂存内容，不能只依赖忽略规则。

## 15. 性能与资源管理

以下是本项目起始目标与建议配置，不是 Herdr 当前限制或已经达到的性能。先实现可测量机制，再根据 16GB 设备实测调整并记录原因。

| 项目 | 起始策略 |
|---|---|
| 文本 | 先探测大小；大文本先显示不超过 512KiB 的片段；完整高亮建议限制在 2MiB 以内，超过后显式降级 |
| CSV/长列表 | 分页或虚拟化，避免一次创建所有单元格/文件节点 |
| 自管内存缓存 | 默认预算 256MiB，可配置；不包含无法直接控制的系统/WebKit缓存 |
| 自管磁盘缓存 | 默认 1GiB，上限、逐出策略和清理入口可配置 |
| 远程自动获取 | 第一版建议不超过 64MiB，超限先提示，不后台下载数 GB 文件 |
| 大图片 | 先检查像素尺寸和估计解码量，优先缩略解码 |
| 用户反馈 | 正常条件下约 200ms 内显示选择/加载反馈，不把无响应留给用户 |
| 常规文件 | 热启动、小于 1MiB 的本地文本/图片以约 1 秒内可见为优化目标，记录真实结果 |

暂停隐藏视图不必要的轮询、动画和解码，但不能破坏状态。缓存采用有界策略，用户关闭预览时停止相关工作；系统缓存释放可能延迟，要分清资源泄漏和缓存保留。

运行重复开关/切换压力测试，记录本进程和相关 WebKit/Quick Look/媒体进程的资源趋势。要求自管视图、句柄、观察者和任务数量回落，不允许无界增长；不要只凭一次内存截图宣布无泄漏。

首版无需兑现不合理的硬实时性能。指标未达到时给出实测、瓶颈和下一步优化，不删除测试或修改表述掩盖问题。

## 16. 远程工作区与 Agent 联动

### 16.1 远程文件：P1，P0 不得破坏原有识别

保留 machine 身份。远程路径不能直接交给本机 Quick Look/PDFKit；不支持时明确提示“远程预览待实现”，不打开本机同名路径。

后续通过现有已授权连接读取或受控暂存，缓存 key 包含 machine、规范化路径和版本；设置大小、超时、取消、进度、完整性校验和清理。断线/切机后不显示其他机器的旧内容。

远程 `localhost` 指远程机器，不等于当前 Mac。预览远程开发站需要显式端口转发，核查现有授权和端口，不自动暴露公网。

### 16.2 手动发送上下文：P1

先提供复制路径、选区和引用。发送给 Agent 时让用户选择当前可用目标，显示拟发送文本，再确认。

默认发送文件引用和有限选区，不自动上传整个二进制文件。消息应携带工作区、机器和必要行号；目标机器不匹配时阻止或明确转换路径。

不能把自然语言注入普通 Shell，不能在目标 Agent 已退出时把审查文字当命令执行。要验证目标身份和实际通信 API；不确认送达时标为结果未知，禁止自动重发导致重复操作。

### 16.3 浏览器自动操作：P2

用户首先需要的是自己能在 Herdr 内浏览与预览，不要把自动化作为所有功能的前置条件。

若实现，必须控制用户看见的同一个 page/view ID；不能另开一个隐藏 Chrome 冒充同步。不要把 Chrome DevTools MCP 接入独立 Chrome 的结果当成 WKWebView 被控制的证据。

先实现受控的导航、页面结构读取、点击、输入、截图与停止；每个操作需指定目标、超时、权限和用户可见日志。页面跳转到新源后重新评估权限。

授权必须由人通过可靠界面作出，网页和 Agent 均不能自授；“停止 Agent 控制”应立即取消队列并撤销本次访问。支付、发送消息、删除、上传等有副作用行为需单独确认。

不要把 JS 注入采集到的少量错误宣称为完整 DevTools 网络/控制台能力。暂未实现的自动化能力应保持关闭。

## 17. 实施里程碑与继续推进规则

### M0：盘点、建库、隔离

读取已有代码和文档；建立本地项目、环境报告、能力矩阵、任务表、版本锁和测试启动器。通过实际连接身份验证 app/core 隔离。

交付：可重现环境说明、无生产改动、能安全启动与关闭测试环境。

### M1：原生承载垂直原型

按第 07 节先测试 WebView、文档、媒体的宿主承载。解决最基本的焦点、遮挡、隐藏与销毁。输出架构决定，不把大量 UI 美化放在这个阶段。

交付：一个在隔离 Herdr 主窗口真正运行的最小样例及测试证据；或明确阻断和仍可继续的模块。

### M2：文件树、标签与内容路由

复制并扩展 Files，不修改正式内置文件。完成共享 ResourceRef、标签规则、类型探测、文本/Markdown/图片、加载状态、快速切换和文件监听。

### M3：完整本地预览与浏览器

整合 PDF、Office、音视频；完善浏览器地址栏、导航、本地开发站、HTML 信任模式；完成所有 P0 常规样例测试。

### M4：稳定性、安全与兼容性

执行焦点、遮挡、切换、资源、异常路径和安全测试。与实际存在的布局/Mods 组合验证。没有安装的 Threads/T3/Space Folders 不宣称已兼容，也不为了测试自动安装它们。

### M5：可重现构建、安装、回退

从干净源码按锁定版本构建一次；验证 Mod 版与完整增强版的差异、安装清单、卸载和回退。正式安装前提供精确变更清单并等待批准。

每完成一个可运行里程碑，运行相应测试、更新文档并本地提交，再继续下一阶段。不要每完成一小项都停下来问是否继续；权限或不可逆操作才需要确认。

## 19. 安装、升级与回退

项目需要提供可执行入口，命名可调整，但 README 中必须与实际脚本一致：

```text
scripts/doctor
scripts/prepare-upstream
scripts/build
scripts/dev
scripts/test
scripts/package
scripts/install
scripts/uninstall
scripts/rollback
```

不要只创建空脚本。每个脚本有帮助、参数校验、明确退出码和可读错误。构建/安装步骤不能以“请手工改几个文件”作为唯一方案。

安装流程要求：

1. 支持预检和 dry-run，先列出要新增/改动的路径和权限。
2. 读取目标实际版本，拒绝不兼容安装，说明升级/构建方案。
3. 对将要修改的用户文件做时间戳备份和内容指纹；记录本项目安装清单。
4. 默认安装为新 Mod、新布局或独立个人 App，不覆盖内置 Files 和正式应用。
5. 合并快捷键时逐项查冲突，不用整份 keys.json 替换用户配置。
6. 重复安装应幂等；失败时不留下半安装状态。
7. 区分应用配置目录和实际个人构建路径；完整预览依赖的宿主版本要显示。
8. 不假设符号链接能热更新；依据实际加载行为选择复制或链接，并测试更新方式。

卸载/回退只能删除安装清单中、仍属于本项目且未经用户修改的内容。用户后来编辑过的文件先提示，不盲目覆盖。禁止删除整个 `~/.config/herdr-app`、现有工作区、Agent 历史或浏览器资料。

完整个人构建的升级需先在隔离副本应用新上游、重跑核心测试，再由用户确认切换。上游更新冲突或补丁失败时保持已知可用版本，不强推升级。
